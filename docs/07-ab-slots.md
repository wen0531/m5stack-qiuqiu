# M5Stack 手表 A/B 双系统 —— 需求与设计说明

## 1. 这是什么

给 M5Stack StopWatch（ESP32-S3R8，16MB Flash）加入 **A/B 双固件槽**能力：
手表上同时保存两份可独立启动的固件，用户可以在**手表界面上**一键切换、一键备份，
不需要 USB、不需要电脑。

## 2. 解决什么问题

当前痛点（真实发生过）：

1. 刷入新固件后设备起不来，**只能靠用户物理拔插 USB** 才能恢复；
2. 手上没有"可用的旧版本"——每次实验都拿唯一一份固件冒险；
3. 一旦刷坏，手表在用户离开电脑期间完全不可用。

目标：

- 任何一次刷写出问题，都能**不依赖电脑**切回可用系统；
- 新系统启动失败时**自动回滚**，用户无感知；
- 保持一份已验证固件作为备份，随时可切。

## 3. 用户故事

| 编号 | 场景 | 期望 |
|---|---|---|
| U1 | 我想换回旧系统 | 设置 → 系统槽位 → 切换 → 自动重启进入另一系统 |
| U2 | 我刚刷好一个能用的版本 | 设置 → 备份当前系统 → 另一槽变成同样的固件 |
| U3 | 新固件启动就死机 | 重启若干次后自动切回旧系统，用户只需等 |
| U4 | 我想知道当前用的是哪个系统 | 设置页显示 A/B 槽状态与当前运行槽 |

## 4. 功能需求

### F1 槽位信息查询
- 列出 A（ota_0）、B（ota_1）两个应用分区；
- 每个槽显示：是否有效（镜像魔数 0xE9 + 镜像头校验）、大小、是否当前运行。

### F2 手动切换
- 校验目标槽有效 → 写 otadata → 重启；
- 目标槽无效 → **拒绝切换**并提示，绝不允许切到空槽。

### F3 克隆（备份）
- 把当前运行槽的固件完整复制到另一槽（4.9MB 分区，实际 ~3MB）；
- 复制通过 `esp_ota_begin/write/end` 完成，结束时会校验镜像；
- 复制期间禁止进入 light sleep（持电源门禁）。

### F4 自动回滚（准确的语义）
- 启用 `CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE`（**需要 bootloader 一起更新**，只刷 app 不生效）；
- 新镜像首次启动状态为 `NEW → PENDING_VERIFY`；
- 应用在启动 30 秒后做**最小自检**（主循环存活 + BLE 栈已初始化），通过则
  `esp_ota_mark_app_valid_cancel_rollback()` 确认，状态变 `VALID`；
- **若镜像启动后复位且从未确认**，下一次 bootloader 将其判为 `ABORTED` 并回退到另一槽；
- **重要限制**：如果固件是"卡死不复位"（不是重启），标准机制不会自动回退。
  因此固件必须启用任务看门狗 panic（10 秒）产生复位，回滚才会触发；
- 若 90 秒仍未确认，应用主动调用 `esp_ota_mark_app_invalid_rollback_and_reboot()` 回退。

### F5 界面入口
- 设置页新增 "System Slots" 分组：
  - "Switch to other slot"
  - "Clone current to other"
- 操作中显示进度文案，完成后提示结果。

### F6（未实现，后续）开机选单
- 开机 5 秒内按 B 键可切换到另一系统，不按键默认进 A；
- 在应用层实现，**不修改 bootloader**。

## 5. 非功能需求

| 项 | 要求 |
|---|---|
| **不依赖电脑** | 切换/克隆全部在手表上完成 |
| **不允许变砖** | 任何路径都不能让两个槽同时无效 |
| **断电安全** | otadata 写入是原子的；克隆中断只会让目标槽无效 |
| **功耗** | 克隆/切换时持 `ESP_PM_NO_LIGHT_SLEEP`，完成后释放 |
| **不改 bootloader** | 只用 ESP-IDF 官方 OTA/分区 API |
| **设置共享** | 两槽共用 NVS（蓝牙/亮度/闹钟设置保留） |

## 6. 设计要点

```
Flash 布局（16 MB）
├── 系统区 ~64KB（nvs / otadata / phy_init / coredump）
├── ota_0  4.94 MB   ← A 系统
├── ota_1  4.94 MB   ← B 系统
└── storage 4 MB     ← FAT（设置、音效）
```

- 切换 = 写 `otadata`（8 KB）+ `esp_restart()`
- 克隆 = `esp_ota_begin(other)` → 循环 `esp_partition_read` / `esp_ota_write` → `esp_ota_end`
- 有效性判定 = 分区首字节为 `0xE9` 且 `esp_ota_get_partition_description()` 成功
- 回滚 = bootloader 特性 + 应用 30 秒后确认

## 7. 风险与边界

| 风险 | 缓解 |
|---|---|
| 两槽都为空（出厂状态） | 拒绝切换，提示"另一槽无固件" |
| 克隆到一半断电 | 目标槽被标记无效，仍可正常启动当前槽 |
| 新固件"能启动但功能异常" | 自检只覆盖"主循环+BLE"，更深的功能异常需用户手动切回 |
| 卡死不复位 | 依赖任务看门狗（已启用 panic，10 秒）产生复位 |
| 只刷 app 不刷 bootloader | 回滚不生效；首次启用本功能必须完整刷写（含 bootloader） |
| 两槽固件版本不同、设置格式不兼容 | **已接受**：A/B 只保护固件，不保护 NVS/FAT；回滚后旧固件可能读到新格式配置 |
| 克隆覆盖唯一备份 | 克隆前**完整校验源镜像**，失败则不动目标；但语义上确实会覆盖旧版，UI 需提示 |
| 克隆耗时 ~15 秒阻塞界面 | 显示进度文案；期间禁止睡眠 |

## 8. 验收标准

1. 设置页能看到 A/B 状态，当前运行槽标记正确；
2. 另一槽为空时，点"切换"被拒绝并提示；
3. 执行"克隆"后，另一槽变为有效固件；
4. 执行"切换"后设备重启并进入另一槽（界面状态随之改变）；
5. 人为让新槽固件启动失败（例如刷入损坏镜像），30 秒后自动回滚；
6. 上述操作全程不需要 USB 或电脑。

# 多语言支持

固件内置 10 种界面语言，**不包含完整字库**——每种语言只打包"文案里实际出现的字形"。

## 支持的语言

| 代码 | 语言 | 字体来源 | 体积 |
|---|---|---|---|
| `en` | English | 内置 Montserrat | 0 |
| `zh-Hans` | 简体中文 | Noto Sans CJK SC | ~150 KB |
| `zh-Hant` | 繁體中文 | Noto Sans CJK TC | ~150 KB |
| `ja` | 日本語 | Noto Sans CJK JP | ~160 KB |
| `ko` | 한국어 | Noto Sans CJK KR | ~70 KB |
| `fr` | Français | DejaVu Sans | ~30 KB |
| `de` | Deutsch | DejaVu Sans | ~30 KB |
| `es` | Español | DejaVu Sans | ~30 KB |
| `ru` | Русский | DejaVu Sans | ~35 KB |
| `la` | Latina | DejaVu Sans | ~30 KB |

总计让固件从 3.07 MB 增到 3.23 MB（**+160 KB**）。

> 表里是生成后的近似占用；实际编译进固件的位图体积比 `.c` 源文件小。

## 为什么用子集字体

完整 CJK 字库要 2–4 MB（24 px 全字集），而我们只翻译了 23 条界面文案，
用到的汉字/假名/音节一共一两百个。`lv_font_conv --symbols` 可以只把这些字
光栅化成位图，于是：

- 一门外语成本 30–160 KB，而不是几 MB
- 不需要运行时加载字体、不需要占用 storage 分区

**代价**：改文案后必须重新生成字体，否则新出现的字符会显示成方框。

## 实现结构

```
main/i18n/i18n.h/.cpp          字符串表 + 语言状态 + 字体指针
main/assets/fonts/i18n_*.c     每种语言一套子集字体（自动生成）
tools/i18n/strings.json        文案单一来源（10 种语言）
tools/i18n/build_fonts.py      生成字体
tools/i18n/README.md           贡献者指南
```

## 运行时行为

- 启动时从 NVS 读取语言（`namespace "system"`，key `lang`），默认英文；
- 设置 → Device → **Language: xxx**，点一下循环切换；
- 切换后菜单立即用新语言重建（`_need_rebuild` 标记，在 `onRunning` 里重建，
  避免在 LVGL 事件回调里创建对象）；
- `tr("key")` 查表，找不到 key 时返回 key 本身。

## 语言选择页

设置 → Language 打开一个十语言列表（`setup_workers::LanguageWorker`）：

- 每行用**该语言自己的子集字体**渲染（`i18nFontFor(lang)`），所以一眼能认出
- 当前语言整行高亮（绿色）
- 点一行 → `i18nSetLang()` → worker 结束 → 菜单用新语言重建（`_menu_lang` 变化检测）

> 这是一个"手势滚动 + 点击"的流程，在模拟器的确定性回归里不稳定（滚动惯性受帧时序影响），
> 目前靠人工在模拟器里验证；其余 16 个场景走截图哈希回归。

## 启动器应用名

启动器里的应用名（闹钟/表盘/秒表/球球/设置）也走 i18n：

- mooncake 内部仍保留英文名（日志、控制接口用），只有启动器标签做翻译
- `i18nAppName("AlarmClock")` → 当前语言的显示名
- 标签字体改用 `i18nFont()`（带 CJK 字形），不再用只有拉丁字符的 `MontserratSemiBold26`
- 切换语言后启动器在下一帧自动刷新（检测 `_label_lang` 变化）

## 添加一种语言

1. `tools/i18n/strings.json`：`langs` 加代码、`lang_names` 加显示名、每条文案加翻译
2. `tools/i18n/build_fonts.py`：`FONTS` 里指定字体文件
3. `python3 tools/i18n/build_fonts.py` 生成字体
4. `main/i18n/i18n.cpp` 的 `kStrings` 表加一列，`kFonts` 加字体指针
5. `idf.py build`

详细步骤见 [`tools/i18n/README.md`](../tools/i18n/README.md)。

## 已知限制

| 限制 | 说明 |
|---|---|
| 字形必须预先包含 | 新增文案后不重新生成字体会显示方框 |
| 阿拉伯语/希伯来语 | 需要 RTL 排版，未实现 |
| 泰语/印地语 | 需要复杂文字整形（shaping），LVGL 不支持 |
| 文案长度 | 德语/俄语通常比英文长 30–50%，按钮可能换行，需实机确认 |
| 两份数据源 | `strings.json` 与 `i18n.cpp` 的 `kStrings` 需要人工同步（后续可加生成脚本） |
